Abstract

The rapid advancement of Artificial Intelligence (AI) and web technologies has opened new frontiers for digital transformation in the food service industry. This report presents FoodGenie, an AI-powered food court ordering and discovery platform developed using the MERN stack — MongoDB, Express.js, React.js, and Node.js. The system integrates Large Language Model (LLM) capabilities via the Groq API to provide intelligent, personalised dish recommendations based on user mood, dietary preferences, and budget constraints.

Traditional food ordering applications suffer from "decision fatigue" — a problem that arises when users are confronted with static, unfiltered menus containing hundreds of items. FoodGenie addresses this challenge by embedding a real-time AI concierge — the "Genie" — that acts as a smart food advisor, significantly elevating the user experience and increasing the average order value (AOV).

The frontend is developed with React.js and styled using Tailwind CSS with a premium glassmorphism design language enriched with Framer Motion animations. The backend is a RESTful API powered by Node.js and Express.js, persisting data in MongoDB Atlas. The system supports secure JWT-based authentication, dynamic order tracking, a comprehensive admin command centre, delivery boy management, Razorpay payment gateway integration, and push notifications.

The platform is fully deployed on Vercel using a serverless architecture for the backend API and a Vite-built static bundle for the frontend. Performance optimisations include MongoDB connection caching for serverless environments, lazy-loaded images sourced dynamically from the Pexels API, and code-split React routes.

Keywords: AI Recommendation, MERN Stack, Food Ordering, Glassmorphism UI, JWT Authentication, Groq LLM, Vercel Serverless, Razorpay, Order Tracking, Node.js.

Chapter 1
Introduction

1.1 Background

The global online food delivery market has witnessed exponential growth over the last decade, driven by the convergence of mobile internet penetration, changing consumer behaviour, and the widespread adoption of digital payment systems. According to Statista (2024), the online food delivery segment is projected to generate global revenue exceeding USD 1.65 trillion by 2027, growing at a compound annual growth rate (CAGR) of approximately 10.17%.

Despite this remarkable growth, most food ordering platforms continue to operate on a fundamentally static paradigm — presenting users with long, unfiltered menus and providing little in the way of personalised guidance. This results in "decision fatigue," leading to lower user satisfaction, reduced order frequency, and elevated cart abandonment rates.

The emergence of Large Language Models (LLMs) and accessible AI inference APIs presents an unprecedented opportunity to reinvent the food discovery experience. By embedding conversational intelligence directly into the ordering workflow, a platform can function as a personal gastronomy concierge — one that understands user mood, dietary constraints, and budget to deliver hyper-relevant recommendations in real time.

1.2 Project Overview

FoodGenie is an AI-powered food court ordering and discovery platform built to address these challenges. Developed on the MERN stack — MongoDB, Express.js, React.js, and Node.js — it integrates the Groq LLM API to provide an intelligent "Genie" concierge experience. The platform features a premium glassmorphism user interface, a robust admin dashboard, real-time order tracking, gamification elements, and a serverless cloud deployment architecture on Vercel.

1.3 Objectives of the Project

  • To design and develop a full-stack food ordering web application using the MERN technology stack.
  • To integrate an AI-powered recommendation engine using the Groq API (LLaMA 3.1 model) for personalised, context-aware dish suggestions.
  • To implement a secure, JWT-based authentication and authorisation system with role-based access control (User / Admin).
  • To build a comprehensive Admin Dashboard for real-time management of menus, orders, users, delivery personnel, and revenue analytics.
  • To deliver a premium, responsive, and accessible UI using Tailwind CSS and Framer Motion micro-animations.
  • To integrate the Razorpay payment gateway for secure, multi-mode payment processing.
  • To deploy the entire application on Vercel using a serverless function architecture optimised for low-latency global delivery.

1.4 Problem Statement

The food service and hospitality industry faces a critical challenge in the digital age: delivering a personalised, engaging, and efficient ordering experience to a diverse and discerning user base. Existing food ordering platforms, while functionally adequate, exhibit several systemic limitations:

  1. Static Menu Presentation: Menus are displayed as undifferentiated lists with no contextual filtering based on user preference, mood, or available budget.
  2. Absence of Personalisation: No real-time mechanism exists to adapt recommendations based on individual user behaviour or natural language intent.
  3. Poor UX/UI Design: Many food ordering systems rely on outdated design patterns, resulting in poor user engagement and high bounce rates.
  4. Fragmented Admin Operations: Restaurant owners and food court managers lack a unified command centre to monitor orders, track deliveries, manage inventory, and analyse revenue simultaneously.
  5. Limited Order Transparency: Customers cannot track their order lifecycle in real time, leading to dissatisfaction and repeated support queries.

FoodGenie is designed as a comprehensive solution to all of the above limitations.

1.5 Scope of the Project

The scope of FoodGenie encompasses the following functional domains:

  • Customer-Facing Portal: Home page, menu browsing, AI recommendations, cart management, secure checkout, real-time order tracking, user profile, and order history.
  • AI Concierge Module: A conversational chatbot powered by the Groq LLaMA 3.1 API, accepting natural language input and returning contextualised menu recommendations.
  • Admin Command Centre: Full management of food items, categories, orders, users, delivery boys, revenue analytics, customer reviews, and system settings.
  • Payment Integration: Razorpay gateway for cards, UPI, net banking, and wallets.
  • Deployment & DevOps: Continuous deployment via Vercel with environment variable management and serverless function architecture.

3.1 Introduction

This chapter presents the Software Requirement Specification (SRS) document for the FoodGenie platform. It systematically defines all functional requirements (what the system shall do), non-functional requirements (how well the system shall perform), interface requirements, and system constraints that guided the design, development, and testing of the application.

3.2 Functional Requirements

3.2.1 User Authentication & Profile Management

  • FR-01: The system shall allow new users to register using full name, email address, and password.
  • FR-02: The system shall authenticate registered users using email and password, returning a signed JSON Web Token (JWT) valid for a configurable duration (default: 30 days).
  • FR-03: The system shall enforce role-based access control with two distinct roles: user (Customer) and admin (Administrator).
  • FR-04: Authenticated users shall be able to update their profile including display name, avatar image URL, and taste mood preference (Adventurous, Comfort, Healthy, Energetic).
  • FR-05: The system shall maintain and display a gamification profile comprising XP points, rank (Rookie → Explorer → Foodie → Gourmet → Legend), and count of completed orders.

3.2.2 Menu & Food Discovery

  • FR-06: The system shall retrieve and display all available food items from the database, including name, price, category, description, average rating, review count, and a dynamically sourced Pexels image.
  • FR-07: Customers shall be able to filter food items by category using interactive category tabs.
  • FR-08: Administrators shall be able to Create, Read, Update, and Delete (CRUD) food items and food categories via the admin dashboard.
  • FR-09: The system shall provide a "Build Your Plate" feature that allows customers to compose a custom meal by selecting items from predefined plate-component categories (e.g., Base, Protein, Side, Drink).

3.2.3 AI Recommendation Engine

  • FR-10: The system shall provide a persistent conversational AI chatbot ("Genie") accessible from all customer-facing pages via a floating action button.
  • FR-11: The Genie chatbot shall accept free-form natural language input (e.g., "I want something spicy under ₹200") and respond with personalised recommendations drawn from the live menu.
  • FR-12: The Genie shall use the Groq LLaMA 3.1-8B-Instant model with the complete current menu dynamically injected as the system context for every request.
  • FR-13: The system shall additionally provide a dedicated structured "Recommend" page where users can input budget, mood, and dietary preferences to receive AI-generated dish suggestions.
9

3.2.4 Cart & Checkout

  • FR-14: Customers shall be able to add, remove, and adjust quantities of items in the shopping cart; cart state shall persist across sessions using the browser's local storage.
  • FR-15: The cart page shall display real-time stock availability status for each item and prevent checkout if unavailable items are present.
  • FR-16: The checkout form shall collect delivery address details (street, city, phone number) and the selected payment method.
  • FR-17: The system shall integrate the Razorpay payment gateway to support Cards, UPI, Net Banking, and Wallet payment modes.
  • FR-18: Upon successful payment confirmation from Razorpay, the system shall create an Order document in MongoDB with status "Pending" and paymentStatus "Paid," and clear the cart.

3.2.5 Order Tracking

  • FR-19: Authenticated customers shall be able to view a real-time order tracking page with animated status step indicators for each of their active orders.
  • FR-20: Order status shall progress sequentially through the states: Pending → Preparing → Out for Delivery → Delivered (or Cancelled).
  • FR-21: Upon order delivery, customers shall be prompted to submit a rating (1–5 stars) for the restaurant and the delivery boy, along with optional text feedback.

3.2.6 Admin Dashboard

  • FR-22: The admin dashboard home page shall display real-time aggregate KPI cards: Total Revenue, Total Orders, Active Users, and Pending Orders.
  • FR-23: Admins shall be able to perform full CRUD operations on food items, food categories, and delivery boy records.
  • FR-24: Admins shall be able to view all orders, update their status, and assign or reassign delivery boys to any active order.
  • FR-25: The analytics section shall display revenue trend charts over configurable time periods and a ranked list of top-selling food items.

Chapter 4
Technology Used

4.1 Frontend Technologies

4.1.1 React.js (v18)

React.js is an open-source JavaScript library developed by Meta for building component-based user interfaces. FoodGenie utilises React's Virtual DOM for efficient declarative re-rendering, React Hooks (useState, useEffect, useContext, useCallback) for state and side-effect management, and React Router v6 for client-side navigation including nested protected routes for the admin panel.

4.1.2 Tailwind CSS (v3)

Tailwind CSS is a utility-first CSS framework that enables rapid, consistent UI development through composable class names. FoodGenie extends the default Tailwind configuration via tailwind.config.js to define a custom design token system — including the glassmorphism dark colour palette (dark-900, dark-800, etc.) and primary accent colours — ensuring visual consistency throughout the application.

4.1.3 Framer Motion

Framer Motion is a production-grade React animation library. It powers all page transitions, hover micro-interactions, skeleton loading screen animations, and the cinematic animated order-status timeline in FoodGenie. The AnimatePresence component enables smooth enter/exit animations when routes are mounted or unmounted.

4.1.4 Zustand

Zustand is a lightweight, unopinionated global state management library for React applications. FoodGenie uses the useAuthStore Zustand store to manage authentication state (user object and JWT token) globally, persisted to localStorage, without the boilerplate overhead of Redux or Context API.

4.1.5 Axios

Axios is a promise-based HTTP client for the browser and Node.js. All API calls from the frontend to the backend are channelled through a centralised Axios instance configured in /src/api/, which automatically injects the JWT Authorization header via a request interceptor, reducing repetitive code across components.

4.1.6 Vite

Vite is a next-generation frontend build tool offering near-instantaneous Hot Module Replacement (HMR) during development, powered by native ES modules. Production builds are optimised through Rollup with automatic code splitting, tree shaking, and asset hashing for optimal caching.

14

4.2 Backend Technologies

4.2.1 Node.js (v18+)

Node.js is an open-source, cross-platform JavaScript runtime built on Google Chrome's V8 engine. Its non-blocking, event-driven I/O model makes it ideal for building scalable, concurrent network applications. FoodGenie's entire backend is authored in Node.js, enabling a unified JavaScript codebase across both frontend and backend tiers of the stack.

4.2.2 Express.js (v4)

Express.js is a minimal and unopinionated web application framework for Node.js. FoodGenie's backend uses Express to define a RESTful API with ten route modules, apply CORS and Morgan middleware, parse JSON request bodies up to 10 MB, and export the Express app instance as a Vercel Serverless Function handler.

4.2.3 MongoDB & Mongoose

MongoDB is a document-oriented NoSQL database that stores data in flexible, JSON-like BSON documents, allowing schema evolution without migrations. Mongoose is the Object Data Modelling (ODM) library providing schema definition, type casting, validation, middleware hooks (pre/post save), and query helper methods. 4.3 AI & External API Integrations

4.3.1 Groq API – LLaMA 3.1-8B-Instant Model

Groq Inc. provides ultra-low-latency LLM inference through its proprietary Language Processing Unit (LPU) architecture, which delivers throughput significantly faster than GPU-based alternatives. FoodGenie's /api/chat route fetches the entire live menu from MongoDB, formats it as a system context string, and forwards the user's natural language prompt to the llama-3.1-8b-instant model using the Groq OpenAI-compatible REST endpoint. Typical end-to-end latency is under 800 ms.

4.3.2 Pexels API

The Pexels API provides programmatic access to a curated library of over 3.2 million free, high-resolution stock photographs. FoodGenie queries images dynamically by food item name, ensuring visually rich menu cards without the storage overhead of self-hosted images.

4.3.3 Razorpay Payment Gateway

Razorpay is India's leading payment gateway, supporting Cards, UPI, Net Banking, and Digital Wallets. FoodGenie integrates Razorpay's Node.js Server SDK to create server-side payment orders, and its client-side JavaScript checkout SDK to render the payment modal in the browser during the checkout flow.

4.4 DevOps & Deployment Infrastructure

4.4.1 Vercel – Serverless Platform

Vercel is a cloud platform specialising in frontend hosting and serverless function execution. FoodGenie's deployment uses Vercel's Serverless Functions feature for the Node.js/Express backend (exported via api/index.js) and a pre-built Vite static bundle for the frontend, all served from a single Vercel project. URL rewriting rules defined in vercel.json route all /api/* requests to the serverless function, while all other requests are served from the static frontend build.

4.4.2 MongoDB Atlas

MongoDB Atlas is a fully managed cloud database service hosted on AWS/GCP/Azure. FoodGenie connects to an Atlas M0 (free tier) cluster over TLS. A global-variable–based connection caching pattern (global.mongoose) is implemented in db.js to reuse active connections across Vercel serverless function cold starts, preventing the creation of excessive database connections under concurrent load.

5.2.1 Database Connection with Serverless Caching (backend/src/config/db.js)

This module implements a global-variable connection caching pattern to prevent connection pool exhaustion across repeated Vercel serverless function invocations:

const mongoose = require('mongoose');

let cached = global.mongoose;
if (!cached) {
  cached = global.mongoose = { conn: null, promise: null };
}

const connectDB = async () => {
  if (cached.conn) {
    console.log('✅ Reusing existing MongoDB connection');
    return cached.conn;
  }
  if (!cached.promise) {
    cached.promise = mongoose.connect(process.env.MONGODB_URI, {
      bufferCommands: false,
    }).then((mongoose) => {
      console.log(`✅ MongoDB Connected: ${mongoose.connection.host}`);
      return mongoose;
    });
  }
  cached.conn = await cached.promise;
  return cached.conn;
};

module.exports = connectDB;

5.2.3 AI Genie Chat Route (backend/src/routes/chat.js)

The chat route fetches the live menu, constructs a system context string, and forwards the user prompt to the Groq API:

const express  = require('express');
const router   = express.Router();
const FoodItem = require('../models/FoodItem');
const axios    = require('axios');

// POST /api/chat – Process AI food recommendation queries
router.post('/', async (req, res) => {
  const { prompt } = req.body;
  if (!prompt) return res.status(400).json({ message: "Provide a prompt" });

  try {
    // 1. Fetch live menu context from MongoDB
    const allItems   = await FoodItem.find({ isAvailable: true });
    const menuContext = allItems
      .map(item => `- ${item.name} (${item.category}): ₹${item.price}`)
      .join('\n');

    // 2. Call Groq API with menu context + user prompt
    const response = await axios.post(
      'https://api.groq.com/openai/v1/chat/completions',
      {
        model: "llama-3.1-8b-instant",
        messages: [
          { role: "system",
            content: `You are FoodGenie AI, a friendly food advisor.
Current Menu:\n${menuContext}\nRecommend from this menu only.` },
          { role: "user", content: prompt }
        ]
      },
      { headers: { Authorization: `Bearer ${process.env.GROQ_API_KEY}` } }
    );

    const answer = response.data.choices[0].message.content;
    res.json({ answer });

  } catch (error) {
    console.error('Groq Error:', error.response?.data || error.message);
    res.status(500).json({ message: "Genie is taking a nap. Try again! 🧞" });
  }
});

module.exports = router;

5.2.4 User Mongoose Model with Pre-Save Password Hashing (backend/src/models/User.js)

const mongoose = require('mongoose');
const bcrypt   = require('bcryptjs');

const userSchema = new mongoose.Schema({
  name:            { type: String, required: true },
  email:           { type: String, required: true, unique: true },
  password:        { type: String, required: true },
  role:            { type: String, enum: ['user', 'admin'], default: 'user' },
  avatar:          { type: String, default: '' },
  tasteMood:       { type: String, default: 'adventurous' },
  rank:            { type: String, default: 'Rookie' },
  xp:              { type: Number, default: 0 },
  ordersCompleted: { type: Number, default: 0 },
  favoritesCount:  { type: Number, default: 0 },
  createdAt:       { type: Date,   default: Date.now }
});

// Pre-save hook: hash password before first save or on modification
userSchema.pre('save', async function(next) {
  if (!this.isModified('password')) return next();
  this.password = await bcrypt.hash(this.password, 10);
  next();
});

module.exports = mongoose.model('User', userSchema);

Chapter 6
Conclusions / Findings / Future Scope

6.1 Conclusions

The FoodGenie project successfully demonstrates the feasibility and value of integrating Large Language Model (LLM) AI capabilities into a production-grade food ordering web application using a modern, full-stack JavaScript technology stack. The following conclusions are drawn from the development, testing, and deployment of the system:

  1. AI Integration is Practically Viable: The Groq API's sub-800ms end-to-end inference latency makes real-time conversational AI a viable feature in consumer web applications, not merely in enterprise or research contexts.
  2. MERN Stack Remains Industry-Relevant: The MongoDB–Express–React–Node.js stack continues to offer an exceptional balance of developer productivity, ecosystem maturity, and deployment flexibility when paired with modern tooling such as Vite, Tailwind CSS, Framer Motion, and Zustand.
  3. Premium UI/UX Increases Perceived Value: The glassmorphism design language and Framer Motion micro-animations created a perceptibly premium user experience, directly differentiating FoodGenie from commodity food ordering templates.
  4. Serverless Architecture is Production-Ready for Full-Stack Apps: Deploying a Node.js/Express backend as Vercel Serverless Functions, combined with MongoDB Atlas connection caching, proved to be a reliable, scalable, and cost-free approach for full-stack student and startup projects.
  5. Zero-Cost Cloud Stack is Achievable: The entire infrastructure — frontend CDN hosting, backend serverless compute, and cloud database — was provisioned and operated at zero monthly cost using free tiers, validating this as a viable model for early-stage applications.

6.2 Findings

  • Serverless functions require careful database connection lifecycle management; without the global.mongoose caching pattern, each cold start would open a new MongoDB connection, quickly exhausting the free-tier connection limit.
  • The Groq free-tier API enforces request-per-minute (RPM) limits that must be handled gracefully in the frontend with appropriate loading states and error messages.
  • JWT-based stateless authentication is well-suited to serverless environments where traditional session storage is not available across function instances.
  • Dynamic image sourcing from the Pexels API improves visual richness significantly but introduces an external dependency for rendering food cards; a fallback image strategy is advisable.
  • Framer Motion animations, while visually impactful, can contribute to bundle size; selective import of only used components is recommended for production optimisation.
